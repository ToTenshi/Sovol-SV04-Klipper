# Slicers

## Common rules

- Start G-code always begins with `M190 S0` / `M109 S0`. This keeps the slicer from heating on its own,
  because `START_PRINT` handles heating, homing, Z tilt and the mesh.
- Mesh area: Cura `%MINX%…` (via `MeshPrintSize.py`), PrusaSlicer/Bambu `{first_layer_print_min[0]}` etc.
  **Don't add offsets in the slicer**, because `START_PRINT` extends COPY/MIRROR itself ([idex](idex.md)).
- COPY/MIRROR: print area 150 × 300 mm in all profiles.
- Accelerations 1500 mm/s² ([input-shaper](input-shaper.md)).

## Bambu Studio

- Standalone user presets (`"inherits": ""`, `"from": "User"`), generated by
  `Bambu Studio Profile/tools/build_profiles.py` from the Voron profiles that ship with Bambu Studio. Only edit the values in the script.
- Placeholders: `nozzle_temperature_initial_layer[n]` (index beyond the end falls back to `[0]`),
  `bed_temperature_initial_layer_single`, `initial_extruder`. Dual: `change_filament_gcode = T[next_extruder]`.
- `travel_short_distance_acceleration` (Bambu default 250) slows short travel moves. This is intentional, left unchanged.
- Bed model: the installer adds `bed_custom_model` (absolute path) only to 300 mm presets.

## PrusaSlicer

- Kept as a config bundle. The installer splits it into user presets
  (`printer/`, `print/`, `filament/*.ini`) and sets `bed_custom_model` to the local path.
- 14 presets that were only compatible with Creality/Prusa printers were removed (they were never visible).

## Cura

- Definitions/extruders/meshes/`MeshPrintSize.py` go into the user folder `<cura>/<version>/…`, which survives Cura updates.
